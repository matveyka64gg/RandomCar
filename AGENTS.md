# AGENTS.md — RandomCar

Инструкция для ИИ-агентов, которые работают с этим репозиторием. Пиши по-русски в ответах, в коде имена на английском, тексты в игре на русском.

## О проекте

3D-аркадная гонка «RandomCar». Одна трасса «Холмы Рандома», 3 круга, 4 машины: игрок и 3 ИИ. Случайные события на трассе с предупреждением. «Хаос» (выкл / умеренно / много) меняет только частоту событий.

Один компьютер, один игрок, без сети. Сетевой режим не трогаем. Игра для себя, друзьям не раздаётся.

- Исходный план: `C:\Users\matvey\.claude\plans\text-3d-moonlit-nygaard.md`.
- Художественная концепция и палитра: `Docs/ArtDirection.md`.
- Библиотека событий (24 идеи, 12 в v1, веса): `Docs/EventLibrary.md`.
- Как запустить и пересобрать: `README.md`.

## Главные требования (директива Visual Excellence)

- Визуальное качество — критерий готовности каждого этапа наравне с работоспособностью.
- **Все значимые 3D-модели делаются в Blender** (через сокет BlenderMCP), экспортируются в FBX и импортируются в Unity. Примитивы Unity — только для блокинга, коллайдеров и мелкой служебной геометрии, не как финальные модели.
- **Мир заранее собран в сцене** `Assets/Scenes/Main.unity`: трасса, машины на решётке, окружение, свет, камеры, объекты событий. В игре мир не пересоздаётся. Процедурная генерация допустима только как инструмент редактора, результат сохраняется ассетами и объектами сцены.
- Единый стиль: «солнечно, сочно, читаемо», палитра из `Docs/ArtDirection.md`, материалы из общей библиотеки `Assets/Art/Materials`.
- После каждого изменения визуала — цикл: компиляция → консоль → скриншот → минимум три найденных недостатка → исправление → повтор → тесты → отчёт «что проверено, что нет».

## Пайплайн контента

1. **Модели:** скрипт в `Tools/Blender/*.py` строит модель кодом (bpy), рендерит превью в `%TEMP%\randomcar\blender`, экспортирует FBX в `Assets/Art/Models`. Запуск:
   `py -3 -I Tools/Blender/blender_client.py Tools/Blender/rc_lib.py Tools/Blender/<скрипт>.py`
   Координаты в скриптах «как в Unity»: x — вправо, y — вверх, z — вперёд; модель смотрит по +Z. Имена объектов в Blender глобальные: после экспорта переименовывать детали, иначе следующая модель получит `.001`.
2. **Материалы:** имена материалов в Blender `M_*` совпадают с библиотекой Unity. Новый материал добавляется в `ArtLibrary.CreateAll()`. Подмена встроенных материалов на библиотечные — `ModelImportRules.RemapMaterials` (через AddRemap: воркеры импорта не видят только что созданные материалы).
3. **Сцена:** `RandomCar/Build Main Scene` (или `unity command script eval "RandomCar.EditorTools.WorldBuilder.BuildAll(); return \"ok\";"`). Пересоздаёт материалы, префабы, меши трассы, сцену `Main.unity`, запекает зонд отражений. Ручные правки в `Main.unity` будут перезаписаны — постоянные изменения вносить в WorldBuilder.
4. **Что создаётся в игре динамически:** ничего из мира. Объекты событий — заранее размещённые выключенные экземпляры (по одному на тип) под `Events`; в игре они только включаются. Частицы — дочерние системы, только запускаются.

## Правила игры (их нельзя нарушать)

Проверяются тестами `EventFairnessTests` и ограничениями в `FairnessLimits` + `CarController.Apply*`.

- Два тяжёлых события подряд не выпадают. Тяжёлые: ракета и танк.
- Предупреждение каждого события не короче 1.5 с. Эффект стартует только после предупреждения.
- Цель выбирается равновероятно из всех 4 машин. Позиция в гонке не учитывается.
- Событие не решает гонку: замедление не длиннее 1.5 с и не ниже 45% скорости, буст ровно 2 с и не больше +25%, толчки без урона и выбывания, никаких постоянных изменений. Машины, упёршиеся в столбы, выталкиваются на свободную половину.
- Зона опасности не шире половины дороги (радиус ≤ 3 м). Зона ставится туда, где цель окажется к концу предупреждения, на её полосе ±1 м (для червей, банана, танка, столбов — чуть впереди, чтобы событие было видно).
- Хаос меняет только частоту: выкл — событий нет, умеренно — каждые 20–30 с, много — каждые 8–12 с.
- Плохие и хорошие события весят одинаково (6.0 / 6.0). Если тяжёлые временно исключены, веса остальных плохих растягиваются, баланс 50/50 сохраняется.
- ИИ видит те же предупреждения, что и игрок, и реагирует с вероятностью 70% (физические препятствия объезжает всегда).

## Правила работы с репозиторием

- Сторонние ассеты (модели, текстуры, звуки, шрифты из сети и магазина) не добавлять без спроса.
- Не подключать Unity Analytics и никакую телеметрию. `UnityConnectSettings.m_Enabled` включился сам при сборке (проект привязан к облачному проекту); Analytics, Crash Reporting, Performance Reporting выключены. Решение по флагу — за пользователем.
- Установка, скачивание больших файлов и изменение системных настроек только с подтверждения пользователя.
- Перед работой с редактором читать скилл `unity-cli`.
- Не коммитить и не пушить без запроса.

## Проверка

- **EditMode-тесты** (редактор открыт): `unity command test run --mode EditMode --project-path <путь>`. Batch `unity test` при открытом проекте не работает.
- **Play-режим через Pipeline 0.9.1** (имена команд отличаются от документации скилла, смотреть `unity command --tag <тег>`):
  - `editor.playmode start` / `stop`, затем обязательно `editor.playmode set_run_in_background` (иначе редактор без фокуса замирает: `playerLoopTicking: false`);
  - `script eval "<C#>"` — расширения вроде `Query<T>()` вызывать статически (`UQueryExtensions.Query<T>(root)`);
  - мышь: `runtime simulate_pointer` работает (клики по UI проверены). Клавиатура: `runtime simulate_key` без фокуса окна Unity не доходит до игры — проверять вручную;
  - отладка событий: `EventDirector.Force(id, targetIndex)` и `DebugPauseAt(stage, progress)` (ставит `timeScale = 0` в нужный момент для скриншота); F1–F12 в редакторе — событие на игрока.
- **Скриншоты:** `py -3 -I Tools/Unity/shot.py out.png` (Game view, в Play — с интерфейсом) или `--pos x y z --look x y z --fov f` (временная камера).
- **Сборка:** `RandomCar/Build Windows` или `unity command script eval "RandomCar.EditorTools.BuildScript.BuildWindows(); return \"ok\";"` → `build/RandomCar/RandomCar.exe` (Mono, ~110 МБ).
- Агент не проверяет: ощущение управления, баланс, «красиво ли» на живом человеке. Это проверяет пользователь.
