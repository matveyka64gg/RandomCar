# AGENTS.md — RandomCar

Инструкция для ИИ-агентов, которые работают с этим репозиторием. Ответы и отчёты — по-русски. В коде имена классов, методов, переменных и файлов — на английском. Весь игровой текст — на русском.

## О проекте

3D-аркадная гонка «RandomCar». Развиваем существующий проект, а не пишем игру заново: рабочие системы, стиль и архитектуру сохраняем там, где это разумно.

**Цель v2** (план и аудит: `Docs/Roadmap.md`):

- убедительная аркадная физика на `Rigidbody`: масса, сцепление шин, перенос веса, подвеска, коробка передач, **турбонаддув как часть двигателя**;
- общие события в зонах трассы (не «цель — конкретная машина»), заметно чаще, чем в v1;
- конкурентоспособный ИИ на той же физике, что и игрок, с уровнями сложности;
- три карты: «Холмы Рандома» (существующая), «Город», «Пустыня»; экран выбора карты;
- гараж: выбор машины, характеристики, цвет, диски, спойлеры, локальное сохранение;
- мультиплеер Host + Clients по LAN / Radmin VPN / Hamachi без выделенного сервера; одиночный режим работает без сети;
- графика, короткие кат-сцены, обновлённый интерфейс.

Одиночная игра с ИИ остаётся полноценным режимом. Аккаунты, матчмейкинг, облако, платные сервисы, магазин и микротранзакции не добавляем.

**v3** (план, решения и статус: `Docs/Roadmap_v3.md`): музыкальная система из файлов пользователя, гараж с обвесами под каждый кузов,
окраской, наклейками и своими картинками, автопарк из 10 машин разных классов, ночная карта «Тель-Авив» с шоу «Ракетный дождь».
Покупки в гараже — только за внутриигровые кредиты за гонки и только после подтверждения.

- Художественная концепция и палитра: `Docs/ArtDirection.md`.
- Библиотека событий (идеи, классы, веса): `Docs/EventLibrary.md`.
- Как запустить и пересобрать: `README.md`.

## Главные требования (директива Visual Excellence)

- Визуальное качество — критерий готовности каждого этапа наравне с работоспособностью.
- **Все значимые 3D-модели делаются в Blender** (через сокет BlenderMCP), экспортируются в FBX и импортируются в Unity. Примитивы Unity — только для блокинга, коллайдеров и мелкой служебной геометрии.
- **Мир карт заранее собран в сценах.** В игре мир не пересоздаётся. Процедурная генерация — только инструмент редактора, результат сохраняется ассетами и объектами сцены. Во время гонки из префабов создаются только машины участников (выбор в гараже и сеть этого требуют) и сетевые объекты; объекты событий — заранее размещённый пул.
- Единый стиль: «солнечно, сочно, читаемо», палитра из `Docs/ArtDirection.md`, материалы из общей библиотеки `Assets/Art/Materials`. Новые карты получают своё освещение и материалы, но остаются в этом стиле.
- Реализм не достигается одной постобработкой: геометрия, материалы, свет и композиция работают вместе. Целевое разрешение визуальных проверок — 1920×1080; второстепенные эффекты не должны заметно ронять FPS.
- После каждого изменения визуала — цикл: компиляция → консоль → скриншот → минимум три найденных недостатка → исправление → повтор → тесты → отчёт «что проверено, что нет».

## Стек

- Unity 6000.6.7f1 (в Hub не помечена как LTS; пользователь решил оставить её), C#, URP 17.6.0, Forward+, SSAO, HDR, MSAA 4x.
- Пакеты: `com.unity.pipeline` 0.9.1-exp.1, `com.unity.test-framework` 1.8.0 (из локальной копии редактора), Input System 1.20.1, uGUI 2.6.0 (нужен для EventSystem), **Netcode for GameObjects 2.13.3** (установлен 2026-10-27 с разрешения пользователя; UPM подтянул Unity Transport 6.6.0, Collections 6.6.0, Burst 2.0.0, Mathematics 1.4.0).
- Сеть: решение — в `Docs/Roadmap.md` §3. Код — сборка `RandomCar.Net` (`Assets/Scripts/Net`), ядро `RandomCar` от неё не зависит. Без NetworkObject и спавна NGO: только соединение, одобрение подключения и именованные сообщения (`NetProtocol`). NetworkManager создаётся при первом «Создать лобби» / «Подключиться», одиночная игра его не запускает.
- Ввод только через Input System (`activeInputHandler: 1`). Старый `Input.GetKey` не использовать.
- Интерфейс: UI Toolkit, стили в `Assets/UI/RandomCar.uss`, тема `Assets/UI/RandomCarTheme.tss` (шрифт темы с кириллицей). В USS жирный курсив пишется `bold-and-italic`.
- Звук: эффекты процедурные (`Assets/Scripts/Audio/SoundBank.cs`). Музыка и сирена — **только файлы пользователя** в `Assets/Art/Audio/Music` (подпапка = плейлист, `TelAviv` — плейлист карты); музыку не скачивать и чужие композиции не добавлять. `MusicImport` (AssetPostprocessor) перекодирует неподдерживаемые форматы через ffmpeg (оригиналы — в `Assets/Art/Audio/Originals~`), переносит файлы со словами «сирена/siren/alarm/тревога» в `Assets/Art/Audio/Sfx/<подпапка>` и собирает `Assets/Settings/MusicLibrary.asset`. Один `MusicPlayer` (два источника, плавная смена) на всю игру.
  Озвучка событий пользователя — `Assets/Art/Audio/Sfx/Events/` (`MusicImport`: PCM, распаковка при загрузке, без перекодировки):
  `el-drifto.mp3` — крик шоу EL DRIFTO BUS, оригинальный файл пользователя (SHA-256 в `SpectacleTests`). Не обрезать, не заменять
  синтезом, другой записью или текстом; предупреждение FSBTool «file was truncated» при импорте — свойство исходного файла.
  `hypergamy.wav` — музыка ГИПЕРГАМИИ: вся звуковая дорожка видео пользователя `IMG_5606.MP4` (ffmpeg, PCM, без обрезки и громкости);
  картинка — `Assets/Art/Textures/Events/hypergamy.jpg` (копия присланной). Оба SHA-256 — в `HypergamyTests`; не заменять.
- Конфигурации — ScriptableObject (`EventSettings`, характеристики машин, карты). Параметры не размазывать по скриптам.
- Лучшие времена и настройки: JSON в `Application.persistentDataPath` (`AppData\LocalLow\DefaultCompany\RandomCar\best_times*.json`, `settings.json`, `garage.json` версии 2 — кредиты, машины, сборки, детали). Свои картинки для наклеек — `Decals\<sha>.png` там же (PNG/JPEG до 8 МБ и 4096², уменьшаются до 1024, до 32 штук). Картинки пользователя никуда не отправлять: ни в сеть, ни в аналитику.
- В проекте включён быстрый вход в Play без перезагрузки домена: статические поля переживают сессию. Для `UnityEngine.Object` в статиках проверять `== null` (оператор Unity), а не `??=`. Синглтоны и статические события сбрасывать явно.

## Архитектурные правила

- Один класс — одна ответственность. Раздельно: физика машины и её состояние; визуал подвески и колёс; ввод игрока; ИИ; конфигурация машины; турбина и двигатель; эффекты и интерфейс.
- Игрок и ИИ используют **одну и ту же** модель физики. ИИ не телепортируется, не игнорирует столкновения и не получает физических бонусов. Сложность ИИ — качество решений, реакция и траектория.
- Турбонаддув — часть двигателя. Ускорение от событий («рывок») — отдельная механика с другим названием и индикацией.
- Косметика (цвет, диски, спойлер, обвесы, наклейки) не меняет физику скрыто. Настройка (`CarTuning`: главная пара, подвеска, шины, тормоза) — только компромиссы с явными цифрами в гараже, строго лучших вариантов нет.
- Сборка машины — `CarBuild` (JSON, `Sanitize(catalog)` отбрасывает недопустимое). Будущий хост проверяет чужие сборки этим же методом.
- Гараж не зависит от освещения карты: `GarageStudio` на время показа ставит нейтральный рассеянный свет и делает солнце карты ключевым светом студии, при выходе всё возвращает.
- Сетевой режим не должен ломать одиночный: игровые системы работают без запущенной сети, сетевые компоненты надстраиваются сверху. Хост — единственный источник лобби, состава гонки, старта, событий и результатов. Свою машину считает владелец и шлёт состояние 30 раз/с через хоста; чужие машины — кинематические копии `NetProxy` (интерполяция 150 мс, экстраполяция до 250 мс, колёса/звук по `CarPhysics.RemoteStep`). ИИ считается только на хосте.
- События в сети: место и **сид** (`HazardSpot.Seed`) приходят от хоста, случайные детали события — только через `RaceEvent.RandomRange` (не `Context.Random`), иначе у игроков разойдутся сторона мяча, ветра и т. п.
- Свои картинки-наклейки по сети не передаются: перед отправкой сборки слои `custom:` удаляются.
- Ошибки не скрывать: никаких пустых `catch`, массового отключения проверок и подавления предупреждений компилятора.
- Сторонние зависимости — только обоснованные и согласованные с пользователем.

## Пайплайн контента

1. **Модели:** скрипт в `Tools/Blender/*.py` строит модель кодом (bpy), рендерит превью в `%TEMP%\randomcar\blender`, экспортирует FBX в `Assets/Art/Models`. Запуск:
   `py -3 -I Tools/Blender/blender_client.py Tools/Blender/rc_lib.py Tools/Blender/<скрипт>.py`
   Координаты в скриптах «как в Unity»: x — вправо, y — вверх, z — вперёд; модель смотрит по +Z. Имена объектов в Blender глобальные: после экспорта переименовывать детали, иначе следующая модель получит `.001`. Blender 5.2.3 LTS.
   Детали для кастомизации (спойлеры, диски, обвес) экспортировать **отдельными объектами**, а не склеивать с кузовом; диск — отдельно от шины.
2. **Материалы:** имена материалов в Blender `M_*` совпадают с библиотекой Unity. Новый материал добавляется в `ArtLibrary.CreateAll()`. Подмена встроенных материалов на библиотечные — `ModelImportRules.RemapMaterials` (через AddRemap: воркеры импорта не видят только что созданные материалы).
3. **Сцены:** `RandomCar/Build All` (или `unity command script eval "RandomCar.EditorTools.WorldBuilder.BuildAll(); return \"ok\";"`, ~2–3 мин). Пересоздаёт материалы, префабы, каталоги, три сцены карт и сцену Game, запекает зонды отражений, выставляет сцены сборки (Game первой). Отдельно: `CityMapBuilder.Build()`, `DesertMapBuilder.Build()`, `WorldBuilder.BuildGameOnly()`. После сборки карты в редакторе открыта она — перед Play открыть `Game.unity`. Ручные правки в сценах будут перезаписаны — постоянные изменения вносить в билдеры.
   Ловушки Blender → FBX: вложенные объекты с поворотом портятся экспортом (диски экспортируются соседями колёс и переносятся в колёса сборщиком префабов); `box()` строит вершины в мировых координатах — поворачивать только построенное в начале координат; URP рисует одну сторону — нормали внутренних стен смотрят внутрь; текст в превью Blender зеркален, в Unity читается правильно.
4. **Что создаётся в игре динамически:** машины участников из префабов (с этапа B/E) и сетевые объекты. Объекты событий — заранее размещённые выключенные экземпляры под `Events`; в игре они только включаются. Частицы — дочерние системы, только запускаются.

- **Модели** собирает генератор `Tools/Blender`: `rc_lib.py car_body.py car_parts.py car_details.py car_designs.py car_build.py kits.py car_run.py`.
  Детали класса машины — `CLASS_DETAILS` в `car_details.py` (молдинги, антенна, решётка, поворотники, секции фонарей,
  третий стоп, порог, брызговики, каркас), дизайн переопределяет их в `d["details"]`. Имена объектов модели (`Body`, `Wheel_*`,
  `Rim_*`, `Disc_*`, `Caliper_*`, `Kit_*`, `Tire_*`, `Mark_*`, `SteeringWheel`, `CabinLiner`, `Interior`, `Driver`) — контракт
  со сборщиком префабов и косметикой: не переименовывать.
- **Материалы огней** (`M_LightHead`, `M_LightDrl`, `M_LightTail`, `M_LightReverse`, `M_LightAmber`) — контракт с `CarLights`:
  свечение меняется блоком свойств по слоту материала. Шлем пилота — материал крыши (`M_PaintRoof`, красится как крыша).
- **Кузов составной**: два `BoxCollider` на корне (низ до кромки капота + кабина до крыши, уже низа). Габариты кузова брать из
  `CarController.BodyBounds`, а не из `GetComponent<BoxCollider>()` (камера из салона, пулемёт, пузырь защиты).
- **Характер** — раздел `CarSpec` (`SteerSpeed`, `AirLeveling/AirDamping/AirSteer`, `KnockResistance`, `Bounciness`,
  `BodyFriction`, `LandingBounce`); значения задаёт `PhysicsAssets.Fill` (сброс — `RandomCar/Reset Car Specs`). Стойкость к ударам
  масштабирует силу события **до** пределов текущего Хаоса — правила «умеренно» не нарушаются.
- **Визуал** (`CarVisuals`): крен/клевок/проседание кузова (`BodyMotion`, амплитуда из `CarSpec.LeanPerG`) — только вид; колесо не
  уходит в арку глубже `CarWheel.ArchRoom` (меряет сборщик префаба лучами по сетке кузова): мультяшный крен занимает только
  оставшийся запас, сжатие сверх арки визуально приподнимает кузов.
- **LOD**: салон, пилот, руль, тормоза — без теней и в `LODGroup` на `Model` (прячутся, когда машина меньше ~7% высоты экрана).
- Проверка: `CarPhysicsLabTests` (все 10 машин: разгон, тормоз, поворот, занос, прыжок, стены, удары, арки, характеры),
  `RandomCar/Car Character Report`.

## Правила событий (их нельзя нарушать)

Проверяются тестами `EventFairnessTests` и ограничениями `FairnessLimits` + методами эффектов машины.

**Хаос v5 «MAXIMUM CHAOS» (2026-10-29, по заданию пользователя): «безумие» — стандарт, баланс не важнее веселья.**
Пользователь явно отменил для «безумия» и «абсурда» требования честности: увернуться можно не всегда, машина может улететь
с трассы, кувыркаться и терять управление. Правила ниже про предупреждение 1.5 с, проезд, «не ближе запаса на реакцию»,
одно тяжёлое, пределы подброса 13 м/с и удара 12 м/с, воздушный поводок действуют **только в «умеренно»** (и частично в «много»);
«безумие» и «абсурд» живут по своим правилам:

- Уровни Хаоса: выкл / умеренно / много / **безумие (стандарт, выбран по умолчанию; старый выбор в settings.json один раз заменён)** / **абсурд**.
- Два потока: обычные события (участки трассы) и **трюки** (`EventDefinition.Gag`, `GagEvent`) — мгновенные происшествия рядом с машиной.
  v5.1 (после отзыва пользователя «перебор, неиграбельно»): «безумие» — события 1.8–2.6 с, трюки 0.7–1.1 с, вместе ~раз в 0.5 с
  (замер: средн 0.48 с), до 8 событий и 8 трюков сразу; **«абсурд»** — прежний темп v5: события 0.9–1.4 с, трюки 0.22–0.42 с,
  вместе каждые ~0.2 с (замер v5: средн 0.21 с). В самого игрока в «безумии» — ~каждый пятый трюк, после полёта 5 с без прямых ударов.
- Накал в «безумии» стартует с 3-й ступени: тяжёлые, комбинации, сцены — с первой секунды; эскалация по кругам — только добавка.
- Место: обычные события — в 16–120 м перед машиной (предупреждение вдвое короче, не меньше 0.8 с); трюки — по прогнозу движения
  машины: под колёсами, на её полосе, на обочине рядом, сверху, вокруг неё. Машину, которая ещё летит или приземлилась меньше 2.5 с
  назад, трюки бьют «мимо» (соседняя полоса, чуть впереди) — хаос вокруг не стихает, а машина успевает проехать.
- Сила (`ChaosPower`): «умеренно» — пределы v4 (FairnessLimits); «безумие» (v5.1) — сила ×0.8, подброс до 30 м/с (высота ~25 м),
  отброс до 24 м/с, закрутка до 8 рад/с, удар тела до 32 м/с, 1.1 с кувырка; «абсурд» — подброс до 44 м/с (с мультяшной тяжестью
  полёта ×1.6 — высота до ~50 м), отброс до 34 м/с, закрутка до 12 рад/с, удар до 46 м/с, 1.9 с кувырка. Поводка в обоих нет. Остаются технические пределы: скорость тел и машин не бесконечна, «потолок» 48 м над точкой подброса.
- «По течению гонки»: удар не отбрасывает к старту (вдоль трассы машина летит не медленнее 20 м/с), поперёк — обычно приземляется
  в пределах ~18 м за краем дороги (каждый пятый удар — «без тормозов»); после приземления машина разворачивается по трассе и
  сохраняет ход. Перелёт вдоль трассы засчитывается в прогресс (до 260 м), перелёт через шпильку на чужой участок — нет.
- Цепные реакции: ударная волна (мины, бочки, мина-сюрприз, кувалда, наковальня, жёсткое приземление) отбрасывает машины и тела и
  поджигает мины/бочки — звено +1, не дальше 8 звеньев, не больше 40 волн в секунду; летящая машина сбивает другие («бильярд»);
  сильный подброс → на месте приземления новый трюк (не дальше 3 звеньев). Взрывы оставляют копоть, удары — трещины (пул, тают).
- Сторож: улетевшую далеко в песок и стоящую там машину возвращает через 1.8 с, упавшую ниже дороги — через 1.6 с, сторож
  продвижения не считает время в воздухе; лёг на крышу — мультяшный переворот через 0.45 с.
- ИИ в «безумии» не тормозит перед опасностями (их всегда много), вне дороги возвращается быстро; трюки ИИ не объезжает.
- Проверка — `EventDynamicsProbe` (блок «ХАОС v5»): частота всех запусков, запусков за 10 с, расстояние до «своей» машины,
  подбросы и высоты, время в воздухе, причины медленной езды, цепные реакции, память. Отладка: `EventDirector.AutoLaunch = false`
  и `Force(id)` (трюк — рядом с игроком).

Реализация (правила v3, 2026-10-28): `EventDirector` (расписание и накал, пул по 3 экземпляра), `EventPlacer.TryPlaceAhead` (место впереди игрока, честность, неналожение, прямые), `EventScheduler` (выбор и правило тяжёлых), `EventIntensity` (накал по доле гонки), `LanePicker` (полосы по очереди и «на твою полосу»), `RaceEvent` (стадии: «удар» ждёт подъезда, «зона» держится до проезда). Проверка динамики — `EventDynamicsProbe`. Тесты: `EventFairnessTests`, `EventPlacementTests`, `EventPacingTests`, `ChaosTests` (хаос v4: совместимость, сцены, баланс при фильтрах, проезд у мин, узкие дороги). Хаос v4: `ChaosRules`/`ChaosComposer` (комбинации и сцены), `ChaosFx`, `ChaosBody`; `EventPlacer.Conflicts` разрешает наложение по правилам хаоса.

- События ставятся **на трассе впереди живых игроков** (в сети — по очереди) на расстоянии, которое игрок проедет за предупреждение + запас на реакцию + время прочитать сцену (55–330 м). Никогда позади и не на другом конце трассы. Событие не следует за машиной: место на трассе фиксировано. Лидер или отстающий как таковые целью не выбираются (решение пользователя 2026-10-28: события должны быть достижимыми для игрока; это заменило правило v2 «место случайно для любой машины»).
- «Удар» (`Trigger`: мяч, стадо, ракета, ветер, танк, обломки, обстрел) держит предупреждение, пока игрок не подъедет на `TriggerLead` с, но не дольше `FairnessLimits.MaxHoldSeconds`; «зона» (`Sustain`: лужа, столбы, ящики, трамплин, ускорители, перекрытие) держится, пока он не проедет, но не дольше `MaxSustainSeconds`.
- Накал (`EventIntensity`) растёт с долей пройденной гонки: промежуток между событиями ×1.15 → ×0.55, +1 одновременное на высоком накале, тяжёлые — с 1/3 гонки, цепочки (второе событие сразу за первым) — со второй половины, волна из двух событий на каждом новом круге, страховка: впереди у игрока пусто дольше `MaxQuiet` (5 → 2.5 с при «много») — событие сразу. Часть плохих (40 → 70%) — на полосу игрока, остальные — по полосам по очереди.
- Временные волны: карта может просить директор поставить событие по своему расписанию (`EventDirector.LaunchWave`) — «Тель-Авив» ставит «Ракетный удар» вместе с волной ракет и сиреной; правила честности те же.
- Любой участник, оказавшийся в зоне, получает воздействие; одно событие может задеть несколько машин.
- Каждое событие имеет правила появления, зону, длительность, визуальное предупреждение, видимое всем участникам, и завершение. Предупреждение не короче 1.5 с, эффект стартует только после него.
- Опасность не появляется прямо под машиной: в момент появления ни одна машина не должна успеть доехать до зоны раньше конца предупреждения плюс запас на реакцию.
- Опасная зона не перекрывает всю ширину дороги — проезд остаётся всегда. Опасные зоны не накладываются друг на друга без специального замысла.
- Два тяжёлых события подряд не выпадают; одновременно активно не больше одного тяжёлого. Тяжёлые определяются централизованно в `EventSettings`.
- Хаос (правила v4, 2026-10-28, по заданию пользователя «CHAOS OVERDRIVE»): выкл / умеренно / много / **безумие**. Интервал между началами на первом круге: 6.5–8.5 / 3.2–4.4 / 2.2–3.1 с, накал сжимает его до ×0.6 к финалу. Одновременно 3/4/6 (+1 на высоком накале, +2 в «Безумии» к финалу), физических тел не больше 10/16/26. «Безумие» меняет не только частоту: комбинации с первого круга и чаще, сцены, редкие события (`MinChaos`), салют. Новые события открываются с накалом (`MinLevel`), развилка — только на дорогах ≥ 16 м (`MinRoadHalf`).
- Суммарный вес хороших и плохих событий равен (12.4 = 12.4). Если часть событий исключена (тяжёлые, Хаос, накал, ширина дороги, бюджет физики), веса оставшихся **своей стороны** растягиваются, баланс 50/50 сохраняется. Баланс не менять скрытно.
- Комбинации (`ChaosRules`): «поверх участка» — только слой (покрытие, невесомость, ветер, бонусы) или задуманная пара; не два тяжёлых, не два покрытия, не два перекрытия полос; вместе не больше 72% ширины дороги; на дороге уже 16 м поверх участка — только слои. «Сразу за» — что угодно, кроме двух тяжёлых. Сцены — рецепты из нескольких событий; каждый шаг проходит обычные проверки, невозможный пропускается.
- Каждое третье событие ставится впереди одной из машин ИИ (по очереди): игрок и ИИ в сопоставимых условиях.
- Подброс (батут, мина, молот, перчатка, карусель) — `CarController.ApplyLaunch`: вверх не сильнее `MaxLaunchUp` (13 м/с), вбок — `MaxImpulse`, закручивание — `MaxSpin`. После подброса 4 с действует «воздушный поводок»: в воздухе машина доворачивает вдоль трассы и не уходит за край дороги. Удар физического тела или конструкции события меняет скорость машины не больше `MaxEventImpactDeltaV` (12 м/с). Невесомость — не ниже 30% силы тяжести; «мини/гигант» — только вид, не дольше 4 с.
- Сторож продвижения: участник, проехавший вдоль трассы меньше 12 м за 6 с (за ограждением, в заторе), возвращается на дорогу; улетевший на 12 м вниз, 40 м вверх или 60 м вбок — через 1.2 с. Правило одно для всех.
- Физические тела событий (`ChaosBody`): предел скорости и вращения, «бортик» у края дороги, потерянное с карты тело убирается; в сети их считает хост, клиенты получают состояние 20 раз/с (кинематические копии).
- Эффекты не уничтожают машины, не меняют характеристики навсегда и не выбивают из гонки: замедление не длиннее 1.5 с и не ниже 45% скорости, рывок ровно 2 с и не больше +25%, толчки без урона. Застрявшие у препятствий выталкиваются на свободную часть дороги.
- ИИ видит те же предупреждения, что и игрок, и реагирует на них.
- В сети события генерирует только хост; клиенты получают одну и ту же последовательность (место, сид, номер розыгрыша, время запуска по часам хоста — движущиеся конструкции у всех в одной фазе). Что задела машина, решает компьютер, который считает её физику: сигнал (`RaceEvent.Signal` → `MsgSignal`) уходит хосту и от него всем, повтор сигнала безвреден.

## Правила работы с репозиторием

- Сторонние ассеты (модели, текстуры, звуки, шрифты из сети и магазина) не добавлять без спроса.
- Не подключать Unity Analytics и никакую телеметрию. `UnityConnectSettings.m_Enabled` включился сам при сборке (проект привязан к облачному проекту); Analytics, Crash Reporting, Performance Reporting выключены. Решение по флагу — за пользователем.
- Установка пакетов, скачивание больших файлов и изменение системных настроек (в том числе брандмауэра Windows) — только с подтверждения пользователя.
- Перед работой с редактором читать скилл `unity-cli`.
- Не коммитить и не пушить без запроса.
- Крупные изменения делать поэтапно, проверяя каждый этап; рискованные миграции (физика, сеть, разделение сцен) — только после согласования архитектуры.

## Проверка

- **Телеметрия гонки:** `RaceTelemetry` на объекте `Game` → `Report()` (круги всех машин, вне дороги, удары, возвраты, обгоны, эффекты).
- **Динамика событий:** `EventDynamicsProbe` на объекте гонки → `Report()`: где событие возникло относительно игрока, видел ли он его, доехал ли, пока оно шло, кончилось ли раньше, пришлось ли объезжать, самый длинный отрезок без событий, события по кругам. Событие, которое «запустилось», но игрок до него не доехал, — ошибка. Для прогона игрока ведёт `AiDriver` (автопилот).
  Хаос v4 в отчёте: интервалы между началами и число видов по кругам, одновременно событий и физических тел, комбинации и сцены, удары тел о машины, взрывы мин, подбросы, **самый узкий проезд** (по `RaceEvent.CollectBlocks`), события для ИИ и доехал ли ИИ, воздействия и возвраты по участникам, **простой** и у каких событий он был, FPS. Отладка: `EventDirector.Force(id)` и `ForceRecipe(id)` (сцена перед игроком).
- **Полигон испытаний:** `ArenaSelfCheck` из редактора (`flow.StartCoroutine(ArenaSelfCheck.Run(flow, 1))`) или ключи сборки
  `-rc-arena-check N` / `-rc-arena -rc-arena-event id -rc-shot путь.png` — строка «Полигон-проверка: id: …» на каждое событие.
- **Сборка без человека:** `RandomCar.exe -screen-fullscreen 0 -screen-width 1920 -screen-height 1080 -rc-race -rc-map TelAviv -rc-chaos 2 -rc-fpslog -logFile <путь>` — гонка на автопилоте, в лог каждые 10 с средний/минимальный FPS и память (рекорды и кредиты не пишутся).
- **EditMode-тесты** (редактор открыт): `unity command test run --mode EditMode --project-path <путь>`. Batch `unity test` при открытом проекте не работает.
- **Консоль:** `unity command console get --level error --tail 20` и `unity command console status` (флаг `compilationFailed`). Перед проверкой — `unity command console clear`.
- **Play-режим через Pipeline** (имена команд отличаются от документации скилла, смотреть `unity command --tag <тег>`; команды с точкой пишутся целиком, остальные — словами через пробел):
  - `unity command editor.playmode start` / `stop`, затем обязательно `unity command editor.playmode set_run_in_background --enable true` (иначе редактор без фокуса замирает: `playerLoopTicking: false`);
  - `unity command script eval_file --file <путь.cs>` — удобнее, чем экранировать C# в `eval`; расширения вроде `Query<T>()` вызывать статически (`UQueryExtensions.Query<T>(root)`);
  - мышь: `runtime simulate_pointer` работает (клики по UI проверены). Клавиатура: `runtime simulate_key` без фокуса окна Unity не доходит до игры — проверять вручную;
  - отладка событий: `EventDirector.Force(...)` и `DebugPauseAt(stage, progress)` (ставит `timeScale = 0` в нужный момент для скриншота); F1–F12 в редакторе — отладочные события.
  - пакеты: `unity command package search --query <имя>` (только чтение); `package add` — только после согласия пользователя.
- **Скриншоты:** `py -3 -I Tools/Unity/shot.py out.png` (Game view, в Play — с интерфейсом) или `--pos x y z --look x y z --fov f` (временная камера).
- **Физика:** проверять контролируемыми сценариями (разгон, торможение, круг постоянного радиуса, переходка, неровности, столкновение) с числовыми критериями, затем в живой гонке. Компиляция — не доказательство «реалистичности».
- **Сеть:** проверять минимум двумя экземплярами игры (редактор + сборка или две сборки) — подключение, гонка, отключение хоста и клиента.
  Хост в редакторе (Play): `NetSession.Host("7777", true)` — `true` слушает только 127.0.0.1, без запроса брандмауэра; `Autopilot = true` — свою машину ведёт ИИ; `StartRace()`.
  Клиент-сборка: `build/RandomCar/RandomCar.exe -screen-fullscreen 0 -screen-width 960 -screen-height 540 -rc-join 127.0.0.1:7777 -rc-autopilot -rc-ready -rc-name Клиент -rc-norecord -logFile <путь>`; хост-сборка — `-rc-host 7777 -rc-loopback`. `-rc-norecord` обязателен: экземпляры на одном ПК делят `garage.json` и рекорды. Строки лога с `[RandomCar] Сеть:` показывают ход сессии.
  Слушать на всех адаптерах (настоящая игра с друзьями) — только через кнопку в игре; запрос брандмауэра Windows подтверждает пользователь.
- **Сборка:** `RandomCar/Build Windows (Beta)` или `unity command script eval "RandomCar.EditorTools.BuildScript.BuildWindows(); return \"ok\";"` → `Builds/Windows/RandomCar.exe` (Mono, ~220 МБ, + UserContent, README_BETA.txt; служебные папки Burst удаляются).
  Android: `RandomCar/Build Android APK (Beta)` / `BuildScript.BuildAndroid()` → `Builds/Android/RandomCar.apk` (IL2CPP, ARM64, minSdk 26, id `com.matveyka64gg.randomcar`,
  отладочная подпись; переключает платформу — после сборки вернуть Windows). Сборки коммитятся через Git LFS (`Builds/**` в .gitattributes).
  Проверка EXE без человека: `-rc-race -rc-map X -rc-chaos N -rc-fpslog -rc-exit -rc-norecord [-rc-noboxes] [-rc-mobile-ui]` — итог гонки и возвраты
  (`[RandomCar] Возврат на трассу: …, причина, место`) в лог.
- Агент не проверяет: ощущение управления, баланс, «красиво ли» на живом человеке, работу через реальный VPN между разными ПК. Это проверяет пользователь.

1. Компиляция и ошибки консоли. 2. Автотесты. 3. Play Mode, если нужен. 4. Скриншоты значимых визуальных изменений. 5. Минимум три визуальных недостатка найдены и исправлены. 6. Старые функции не сломаны. 7. `AGENTS.md` обновлён.
