### 1.1. Что действительно работает

- Цикл заставка → меню → гонка → пауза → результаты, рестарт без перезагрузки сцены.
- Счёт кругов по секторам (`LapCounter`), защита от езды назад и срезки, позиции, таблица лучших с сохранением в JSON.
- 12 событий с моделями из Blender, метками, частицами, звуком; пул объектов без создания в рантайме; планировщик с правилом тяжёлых и балансом 50/50 (покрыт тестами).
- Процедурный звук, UI Toolkit с кириллицей, настройки громкости/качества/FPS/Хаоса.
- Пайплайн Blender → FBX → Unity и сборка мира кодом редактора (`WorldBuilder`), сборка Windows.
- Рендер: URP Forward+, HDR, MSAA 4x, SSAO, тени 4096 / 4 каскада / 220 м, отражения через запечённый зонд.

### 1.2. Что работает частично или с проблемами

- **Физика машины условная.** `CarController` — `CharacterController` + `MoveTowards` скорости. Нет массы, сцепления, инерции, заноса, переноса веса. Поворот — фиксированные 110°/с при любой скорости, поэтому игроку не нужно тормозить, а шпилька R=24 м проходится на 100 км/ч. Столкновения: скорость просто обрезается.
- **Все машины физически одинаковы** (`MaxSpeed = 28` константой), различается только модель.
- **Визуальная подвеска — анимация.** Крен и клевок считаются от руля и `Acceleration`, а не от сил; колёса не двигаются по вертикали; радиус колеса берётся из bounds.
- **ИИ слабый по устройству:** фиксированная боковая линия, скорость = `skill` (0.82–0.95) × `MaxSpeed`, торможение только по углу к точке прицела, нет учёта кривизны вперёд, обгонов, защиты позиции, реакции на соседей. ИИ не борется с игроком, который едет на 100%.
- **Спидометр** показывает `Speed` — внутреннюю переменную модели, а не фактическую скорость тела (при толчках расходится).
- **Звук мотора** — один зацикленный клип с изменением pitch по скорости; нет оборотов, передач, турбины.
- **Ввод** читает клавиатуру напрямую (`Keyboard.current`), `InputSystem_Actions` из шаблона не используется: нет геймпада, чувствительности, переназначения.
- **Трасса плоская** (y = 0), земля — один `BoxCollider` 3600×3600 м; дорога, бордюры и гравий — только визуальные меши, сцепление и неровности поверхностей физически не существуют.
- **`Main.unity` содержит всё сразу** (мир, машины на решётке, игровые системы, UI) и целиком пересоздаётся `WorldBuilder`; игрок жёстко — машина №0 («Искра»).
- **Модели машин:** кузов, спойлер, воздухозаборник и багажник склеены в один меш `Body`; диск склеен с шиной; стёкла непрозрачные, салона нет. Для кастомизации детали надо экспортировать отдельно.
- **Цветокоррекция в LDR** (`m_ColorGradingMode: 0`) при включённом HDR.
- Мусор шаблона: `Assets/TutorialInfo`, `Readme.asset`, `SampleScene.unity` (`URP.png` в git помечен изменённым).

### 1.4. Технические риски

**Физика**
- Тонкий баланс «аркада ↔ симуляция»: модель шин даёт либо «лёд», либо «рельсы». Снижаем риск ассистами (стабилизация рыскания, помощь контррулём, ограничение пробуксовки), настраиваемыми и одинаковыми для ИИ.
- Шаг физики сейчас 0.02 с (50 Гц) — мало для жёсткой подвески. Нужно 0.01 с (100 Гц) + интерполяция `Rigidbody` для камеры.
- Плоский `BoxCollider` земли и визуальные бордюры: нужны отдельные коллайдеры поверхностей, иначе нет ни сцепления по типу покрытия, ни неровностей.
- Все системы, читающие `CarController.Speed`, `MaxSpeed`, `Locked`, `ResetTo`, `Apply*`, `Bumped` (камера, звук, UI, события, гонка, ИИ), должны получить совместимый API — иначе миграция сломает половину игры.
- Быстрый вход в Play без перезагрузки домена: статические кэши новой физики и сети сбрасывать явно.

**Мультиплеер**
- Физика `Rigidbody` недетерминирована — синхронизировать «одну симуляцию» нельзя; нужна схема с владельцем машины (см. раздел 3).
- Столкновения машин разных игроков видны с задержкой; при больших пингах VPN (Hamachi 50–150 мс) возможны «мягкие» толчки.
- Брандмауэр Windows блокирует входящий UDP у хоста — пользователь должен разрешить сам (системная настройка).
- Hamachi/Radmin: адрес хоста — IP виртуального адаптера (`26.x.x.x` Radmin, `25.x.x.x` Hamachi), не `localhost` и не `127.0.0.1`.
- Netcode for GameObjects 2.13 с редактором 6000.6 (tech stream) — совместимость заявлена реестром, но не проверена в проекте; NGO и быстрый вход в Play — возможны проблемы синглтона `NetworkManager`.
- Тест нескольких экземпляров на одной машине: редактор + сборка или Multiplayer Play Mode (каждый виртуальный игрок — отдельный процесс, это память).

**Несколько карт**
- `Main.unity` смешивает мир и системы — разделение сцен затронет `WorldBuilder`, `GameFlow`, камеры, UI. Нужно сделать один раз и аккуратно.
- Аддитивная загрузка: освещение, skybox, туман, зонд отражений и Volume должны браться из сцены карты (`SetActiveScene`).
- `TrackPath` плоский и ищет ближайшую точку перебором по XZ — для карт без пересечений трассы с собой это работает; мосты/развязки сломают счёт кругов (на «Город» без эстакад).
- Время сборки и объём: 1100 деревьев уже есть; город с домами — следить за draw calls (статический батчинг, GPU instancing, LOD).

**Кастомизация**
- Детали склеены с кузовом — нужна пересборка машин в Blender с раздельными объектами и точками крепления.
- Цвет кузова сейчас — отдельный материал на машину; перекраска через `MaterialPropertyBlock` по слоту материала кузова, без копий материалов.
- Косметика не должна менять массу/аэродинамику — физика берёт параметры только из `CarSpec`, визуальные детали без коллайдеров/масс.
- Сохранение настроек гаража и передача их в сеть (хост раздаёт «гоночную конфигурацию» всем).

## 2. Физика: предлагаемое решение

**Выбор: `Rigidbody` + собственная модель колёс на лучах (raycast suspension) + собственная модель шин.**

Почему не `WheelCollider`: его модель трения (кривые slip) трудно настроить под предсказуемый аркадный занос, он чувствителен к шагу физики и массе, плохо работает на малых скоростях и плохо подходит для «понятного» дрейфа. Своя модель на лучах — 4 луча на машину, прозрачная, полностью настраиваемая, одна и та же для игрока, ИИ и сетевого владельца.

Почему не «тот же `CharacterController`, но лучше»: без сил нельзя получить массу, инерцию, перенос веса и честные столкновения.

### 2.1. Компоненты

| Компонент | Ответственность |
|---|---|
| `CarSpec` (ScriptableObject) | все характеристики машины: масса, центр масс, инерция, двигатель (кривая момента, обороты холостые/макс/отсечка), коробка (передаточные, главная пара, время переключения), турбина (макс. давление, коэффициент момента, задержка, раскрутка/сброс, порог blow-off), привод (FWD/RWD/AWD + распределение), шины по осям (продольное/боковое сцепление, пиковый угол увода, чувствительность к нагрузке), подвеска по осям (ход, жёсткость, демпфирование, стабилизатор), тормоза (усилие, баланс), аэро (Cx·S, прижим), макс. скорость (ограничитель) |
| `CarInput` (struct) | газ, тормоз, руль, ручник — единый вход для игрока, ИИ и сети |
| `CarPhysics` (MonoBehaviour, `FixedUpdate`) | подвеска на лучах → нагрузка на колёса → силы шин (трение по эллипсу) → привод, тормоза, сопротивление качению и воздуха → `Rigidbody.AddForceAtPosition`; ассисты; эффекты событий; состояние машины (скорость тела, скольжение, касание земли) |
| `Drivetrain` (чистый C#) | двигатель, обороты, автомат-коробка с временем переключения и разрывом тяги, торможение двигателем, распределение момента по осям |
| `Turbo` (чистый C#) | давление наддува: цель от оборотов и нагрузки, раскрутка с задержкой, падение при сбросе газа, blow-off, доп. момент = f(давление); тестируется в EditMode |
| `TireModel` (чистый C#) | продольная сила от коэффициента проскальзывания, боковая от угла увода, комбинирование по эллипсу трения, чувствительность к нагрузке, множитель покрытия |
| `Surface` (компонент на коллайдере) + `SurfaceType` (SO) | сцепление, сопротивление качению, «шум» неровностей, тип частиц/следов/звука (асфальт, бордюр, гравий, трава, песок, брусчатка) |
| `CarVisuals` | колёса берут позицию из сжатия подвески, вращаются по фактической угловой скорости колеса, передние поворачиваются на угол из физики; кузов не анимируется отдельно — крен и клевок даёт сама физика |
| `CarFx` | следы шин, дым при скольжении, пыль на гравии/песке, искры при ударах, вспышки/свечение турбины по реальному давлению |
| `CarAudio` | двигатель по оборотам и нагрузке (процедурный синтез гармоник), свист турбины от давления, blow-off, визг шин от скольжения |
| `PlayerDriver` | Input System actions → `CarInput`, чувствительность и сглаживание руля, зависимость руля от скорости |
| `AiDriver` | решение → `CarInput` (тот же интерфейс) |

`CarController` останется фасадом с прежним API (`Speed`, `Locked`, `ResetTo`, `Apply*`, `Bumped`), чтобы гонка, события, камера и UI не ломались разом; внутри он делегирует в `CarPhysics`.

### 2.2. Модель

- Шаг физики 0.01 с, интерполяция тела, центр масс ниже реального для устойчивости, ограничение угловой скорости по крену.
- Подвеска: пружина + демпфер по сжатию луча, стабилизаторы поперечной устойчивости на осях → честный крен, клевок и подъём носа от реальных сил.
- Шина: нормированная кривая (рост до пика, плато, спад после пика) — даёт управляемый занос и восстановление; чувствительность к нагрузке убирает «рельсы» и даёт разницу осей.
- Эффекты событий: замедление — дополнительное сопротивление и ограничение тяги; рывок — продольная сила, не выше +25% и 2 с; толчок — `VelocityChange` с ограничением; «скользко» — множитель сцепления (занос получается из физики, а не из случайного поворота).
- Ассисты (настройка игрока): стабилизация рыскания, помощь контррулём, ограничение пробуксовки, ABS. По умолчанию — «стандарт». ИИ использует тот же уровень «стандарт» — без скрытых преимуществ.
- Защита: перевёртывание на ровной дороге — антикрен и низкий ЦМ; если машина всё же легла/застряла > 2 с — мягкое возвращение на трассу с короткой неуязвимостью (это не телепорт ради выгоды, правило одно для всех).

### 2.3. Масштаб скоростей (требует решения)

Сейчас потолок 100 км/ч и шпилька проходится без торможения. Предлагаю: максимальные скорости машин 170–210 км/ч, шпилька — ~60–70 км/ч (нужно тормозить). Круг «Холмов» станет ≈ 30–35 с. Камера и FOV под это перенастраиваются.

### 2.4. Характер машин (черновик)

| Машина | Привод | Масса | Характер |
|---|---|---|---|
| «Искра» | RWD | лёгкая | маленькая турбина, быстрый отклик, лучше всех в шпильках, любит занос |
| «Комета» | RWD | тяжёлая | большая турбина с заметной задержкой, лучшая макс. скорость |
| «Пчёлка» | AWD | средняя | раллийная, лучше всех на гравии/песке, ровный разгон |
| «Мята» | FWD | лёгкая | атмосферная «малая» турбина, стабильная, прощает ошибки |

Суммарно машины сбалансированы по времени круга на «Холмах» (±1.5%), различаются характером.

### 2.5. Проверки физики (EditMode + контролируемая сцена `PhysicsLab`)

Разгон 0–100 и до макс. скорости; торможение со 100 км/ч до 0 (путь); круг постоянного радиуса (боковое ускорение, устойчивость); резкий руль на скорости (скольжение и восстановление за заданное время); турбина (рост давления, задержка, падение при сбросе, отсутствие роста без нагрузки); переключение передач (без «застревания» на отсечке, разрыв тяги); удар в стену (без прохождения насквозь, без взлёта); проезд бордюров и «гребёнки» (без подпрыгивания и переворота); одна модель у игрока и ИИ (тест на типы компонентов).

**Предложение: Netcode for GameObjects + Unity Transport, прямое подключение по IP без Relay.**

### 3.1. Модель авторитета

- **Хост авторитетен** для: лобби (участники, готовность, карта, машины, косметика), старта и расписания (время сервера), событий (тип, место, сид, моменты стадий), кругов, позиций, финиша и результатов, машин ИИ (их физика считается на хосте).
- **Своя машина симулируется у владельца** (физика у игрока локально, без задержки ввода), состояние (позиция, поворот, скорости, обороты, передача, давление турбины, ввод) рассылается 30 раз в секунду. Хост проверяет правдоподобие (скорость, телепорты) и считает круги по полученным позициям.
- Почему не «всё на хосте»: клиент чувствовал бы задержку руля на величину пинга VPN, а предсказание с откатом для PhysX невозможно без пересимуляции всей сцены. Для гонки с друзьями модель «владелец + авторитетный хост гонки» — стандартный компромисс.
- **Чужие машины** — кинематические прокси: буфер снимков с интерполяцией ~100 мс, экстраполяция по скорости при потерях до 250 мс, плавная коррекция вместо телепорта; колёса/дым/звук турбины берут переданное состояние.
- **Столкновения машин**: каждый владелец сталкивается с кинематическими прокси соседей; толчок, полученный машиной, передаётся её владельцу коротким RPC с ограничением силы.
- **События**: генерирует только `EventDirector` хоста; клиенты получают `EventStart(id, место, сид, время сервера)` и проигрывают визуал по общим часам. Попадание в зону каждый владелец проверяет для своей машины по тем же данным; эффекты проходят через те же ограничители.

### 3.2. Что будет сделано

Создание/закрытие лобби, подключение по `IP:порт` (порт по умолчанию 7777/UDP, настраивается), список участников с пингом, готовность, выбор карты (хост) и машины (каждый), синхронный старт по времени сервера после общих кат-сцен, синхронизация физики/кругов/турбины/результатов, отключение клиента (его машина убирается, в результатах — «сошёл»), отключение хоста (сообщение и возврат в меню), русские сообщения об ошибках (неверный адрес, порт занят, хост недоступен/брандмауэр, лобби заполнено, разные версии игры). В лобби хоста — список его IP с подсказкой «Radmin VPN / Hamachi / локальная сеть».

Сетевой код — отдельная сборка `RandomCar.Net`; одиночный режим не запускает `NetworkManager` и от NGO не зависит.

### 3.3. Что нужно установить (после разрешения)

1. `com.unity.netcode.gameobjects` 2.13.3 — сетевой фреймворк (зависимости, включая `com.unity.transport`, UPM подтянет сам).
2. `com.unity.transport` 6.6.0 — если UPM не добавит его как зависимость.
3. (Опционально, только для разработки) `com.unity.multiplayer.playmode` 3.0.0 — тест 2–4 игроков из одного редактора. Без него проверяем «редактор + сборка».

Системные настройки не меняются. При первом запуске хоста Windows спросит разрешение брандмауэра — его даёт пользователь.

## 4. Карты и сцены

- `Game.unity` — постоянная сцена: `GameFlow`, UI, звук, камеры, сеть, гараж-подиум.
- `Map_Hills.unity`, `Map_City.unity`, `Map_Desert.unity` — грузятся аддитивно; в каждой `MapDefinition`: трасса (`TrackDefinition` SO), решётка, коллайдеры поверхностей, точки облёта камеры, места событий, свет/небо/туман/Volume/зонд отражений.
- Билдер редактора разделяется: общий `TrackMeshBuilder` + билдер на карту. Модели окружения — Blender.
- «Город»: асфальт и брусчатка, тротуары с бордюрами, здания-кварталы, перекрёстки (трасса проходит через них), светофоры, мосты-декор без пересечения трассы с собой, тёплый вечерний свет.
- «Пустыня»: песок (низкое сцепление, пыль), утрамбованный грунт, каньон с перепадами высоты, длинные скоростные прямые, скалы-столбы, жаркое марево.

## 5. Порядок выполнения

Порядок задания A → H сохраняется, с уточнениями внутри этапов:

1. **A.** Аудит, `AGENTS.md`, этот документ. ✅
2. **B. Физика и турбонаддув** на «Холмах»: `CarSpec`, `CarPhysics`, `Drivetrain`, `Turbo`, `TireModel`, поверхности-коллайдеры, шаг 100 Гц, HUD (скорость тела, передача, обороты, наддув), процедурный звук двигателя и турбины, сцена `PhysicsLab` и тесты. Машины начинают создаваться из префабов по конфигурации гонки (нужно и для гаража, и для сети). Временно ИИ адаптируется минимально, чтобы гонка не ломалась.
3. **C. События в зонах**: места событий на трассе, выбор места без цели-машины, проверка «никто не доедет до конца предупреждения», до 2–3 одновременных событий без наложения, одно тяжёлое, новые интервалы, пул по 2 экземпляра, плашка «впереди N м», новые тесты.
4. **D. ИИ**: профиль скорости по кривизне и сцеплению, гоночная линия, обгоны/защита/избегание, реакция на зоны, восстановление после заноса, уровни сложности, тест «не застревает» и «борется за позиции».
5. **E. Карты и гараж**: разделение сцен (первым шагом), экран выбора карты, «Город», «Пустыня», пересборка машин в Blender с отдельными деталями, гараж и сохранение.
6. **F. Мультиплеер** — после согласия на установку пакетов. **Сделано 2026-10-27** (статус и ограничения — `AGENTS.md`, «Этапы и статус»). Отличие от §3.1: толчок от столкновения владельцу не передаётся.
7. **G. Графика и кат-сцены**: материалы, HDR-грейдинг, эффекты, интерфейс, заставка, облёты, финиш.
8. **H. Стабилизация, тесты, сборка, инструкция по подключению.**

Перестановка не нужна: физика (B) должна прийти раньше событий и ИИ, потому что они опираются на её API и скорости; сеть (F) — после карт и гаража, потому что синхронизирует их конфигурацию. Единственная оговорка — архитектура B сразу учитывает режим «машина-прокси» для сети.

## 6. Решения, нужные от пользователя

1. Архитектура физики: `Rigidbody` + своя модель колёс на лучах (рекомендую) или `WheelCollider`.
2. Сеть: Netcode for GameObjects + Unity Transport, прямое подключение по IP; разрешение на установку пакетов (и, опционально, Multiplayer Play Mode) перед этапом F.
3. Масштаб скоростей: потолок 170–210 км/ч с обязательным торможением в шпильке (рекомендую) или оставить около 100 км/ч.
4. Число участников: 4 (люди + ИИ добивают до 4) или расширить решётку до 6.
5. Модель авторитета в сети: «своя машина у владельца, гонка и события у хоста» (рекомендую) или полностью серверная физика (задержка руля у клиентов).
